# CAD Models catalogue pilot

Local pilot of a standalone static CAD catalogue. Both browser backends use
the same typed JSON dataset, built from `data/pilot.json`. Each entry can link to its own sources and preview files.

## Jekyll site

`docs/` is the GitHub Pages source. It contains the Markdown home page, browse
page, manual, contribution guide, model pages, Liquid layouts, and static search
assets. Both SQLite and DuckDB with Parquet remain available in the search form.

Build and preview the saved site locally with Jekyll:

```sh
jekyll build --safe --source docs --destination _site
CATALOGUE_ROOT=_site node scripts/serve.mjs
```

To refresh the generated catalogue assets after a source-data change:

```sh
npm ci
python -m venv .venv
.venv/bin/pip install -r requirements.txt
node scripts/export.mjs
.venv/bin/python scripts/build.py
python scripts/sync-docs.py
```

Then build the Jekyll site again. Edit the home, browse, and manual Markdown
in `docs/`. Model entry stubs and the contribution guide are generated by
`sync-docs.py`. Open http://127.0.0.1:8339 to use the local preview.

## Catalogue data

SQLite uses FTS5 and DuckDB reads static Parquet over HTTP. The original tube
drawing supplies a downloadable model. The other entries are metadata examples
and synthetic search fixtures.

## Future vector search

Generate versioned embeddings from the catalogue titles, descriptions, and tags.
Use the same embedding model for query text. Apply catalogue filters before
ranking candidates by similarity. Preserve exact identifier lookup and keyword
search in both browser backends.

## Agent search

Use `python scripts/search.py 'LS-PS310K'` for read-only JSON results.
Select `--engine duckdb` with the DuckDB Python dependency installed. Use
`--data` to choose a generated catalogue snapshot. See the
[catalogue search skill](skills/cad-catalogue-search/SKILL.md).
